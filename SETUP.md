# FareX Setup Guide

A complete setup and execution guide for the **FareX** smart transit fare system.

---

## 1. Prerequisites

Ensure you have the following installed and available in your `PATH`:

- **Java Development Kit (JDK) 21** or higher
  ```bash
  java -version
  javac -version
  ```
- **Apache Maven 3.8+**
  ```bash
  mvn -version
  ```
- *(Optional for mobile/native builds)*: [GraalVM JDK 21+](https://www.graalvm.org/) configured if building native Gluon images.

---

## 2. Project Architecture

The repository is structured as a Maven multi-module project:

- **`farex-shared`**: Core domain logic, fare engine, discount rules, rewards system, route planner, Mifare Classic card signing (`CardPayload`), and CSV datastore.
- **`farex-server`**: Embedded HTTP backend (port `8080`) providing REST APIs for authentication, PayMongo payment handling, operator tap validation, and an HTML admin panel.
- **`farex-app`**: JavaFX & Gluon desktop/mobile client supporting Passenger, Operator, and Admin interfaces.

---

## 3. Environment Configuration (`.env`)

Create or update the `.env` file in the repository root directory:

```env
# Server Port (default: 8080)
PORT=8080

# Admin credential
ADMIN_PASSWORD=admin123

# PayMongo payment integration
PAYMONGO_SECRET=sk_test_4Kxwf7gEVz238a3rPpqEZ5wF
# Set to 1 to mock PayMongo checkout locally without making external calls
FAKE_PAY=1

# Secret key used for cryptographic HMAC-SHA256 Mifare card signing
CARD_KEY=farex-dev-card-key
```

> [!NOTE]
> The server automatically reads `.env` on launch. If running with `FAKE_PAY=1`, topping up load will immediately succeed without needing an actual PayMongo transaction.

---

## 4. Build & Install

Because `farex-app` depends on `farex-shared` as a Maven dependency, always install `farex-shared` into your local `.m2` repository first before running the app:

```bash
mvn install -DskipTests
```

> [!TIP]
> Run `mvn clean install -DskipTests` whenever changes are made to `farex-shared` (e.g. models, NFC payload signing, or storage classes).

---

## 5. Running the Application

Running FareX requires two terminal sessions: one for the backend server and one for the frontend client.

### Terminal 1: Start the Backend Server

Run the startup batch script from the repository root:

```cmd
.\run-server.bat
```

*Alternative (using Maven)*:
```cmd
mvn compile -pl farex-server
java -cp build-server farex.server.Main
```

The server starts on `http://localhost:8080`.
- **Web Admin Portal**: Open `http://localhost:8080/admin` in your browser (Login password: value of `ADMIN_PASSWORD` in `.env`, default `admin123`).

---

### Terminal 2: Start the JavaFX Client App

From the project root:

```cmd
mvn javafx:run -pl farex-app
```

## 7. NFC / Card Handling

- **Desktop / Simulated Mode**: On a laptop or desktop, `SimCardIO` automatically emulates Mifare Classic RFID cards in memory using signed cryptographic tokens generated by the server.
- **Android / Hardware Mode**: When packaged for Android devices, `farex-app` uses `com.farex.android.ClassicNfc` to interact directly with hardware NFC readers and Mifare Classic tags via sector 1, block 4.

## 8. Common Troubleshooting

### 1. `package farex.shared.card does not exist` or `cannot find symbol`
- **Cause**: `farex-app` was run before the updated `farex-shared` jar was installed into your local Maven cache.
- **Fix**: Run `mvn clean install -DskipTests` from the root directory.

### 2. `java.net.BindException: Address already in use: bind`
- **Cause**: Port 8080 is already in use by a previously running server process.
- **Fix**: Stop the existing Java process using port 8080, or configure a different port in `.env` (e.g. `PORT=8081`) and update `Api.java` accordingly.

### 3. Missing data or corrupt ledger
- Database files reside as simple CSV files inside the `data/` directory. If corrupted during testing, reset them or discard uncommitted changes via `git checkout data/`.
